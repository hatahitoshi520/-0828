# AI Team Studio 事業計画（v0.1）

> Claude Code を「1人のAI」から「役割分担したAIチーム」に組み替える、構築代行＋研修サービス。

## 1. 一言で
**司令塔（Opus）・実働（Sonnet）・監査（Fable）・仕分け（軽量モデル）** の4層構成を、
お客様の開発環境に **diff提示 → 承認 → 適用** の手順で安全に導入する。

## 2. 解決する課題
| お客様の状態 | 困りごと |
|---|---|
| Claude Code を1モデル・1セッションで使っている | 大きいモデルが細かい作業まで抱えて、遅くて高い |
| サブエージェントを作ったが放置 | 役割が重なっていて、どれが呼ばれるか分からない |
| 長いタスクでAIが同じエラーを繰り返す | 「掘る場所が違う」と気づく仕組みがない |
| チームで設定がバラバラ | ~/.claude と .claude/ の管理ルールがない |

## 3. 提供内容（4層の設計）
| 層 | モデル | 役割 | 導入物 |
|---|---|---|---|
| 司令塔 | Opus / effort high | 計画・タスク分解・統合・最終出荷 | settings.json のメインモデル設定 |
| 実働 | Sonnet / effort medium | explorer（読む）・worker（編集・テスト）・researcher（調査） | .claude/agents/*.md ×3 |
| 監査 | Fable（advisor） | ①計画確定前 ②同じエラーの繰り返し ③完了直前 の3回だけ口を出す | CLAUDE.md の相談ルール |
| 仕分け | 軽量モデル（例: Haiku） | 見るファイル・呼ぶツール・再試行/停止などの定型判断 | 軽量サブエージェント or hooks |

**注意（誠実な説明のために）**
- 元ネタの投稿にある「Jev」は公式機能として確認できていない。サービス上は「軽量モデルによる高速ルーティング層」と表現し、実際に使える仕組み（Haikuのサブエージェント、hooks）で作る。
- advisor（`/advisor`・`advisorModel`）の可否はお客様のプラン・バージョン次第。**導入前の診断で実機確認**し、使えない場合は「監査役サブエージェント」で代替する。
- Anthropic社の公式パートナーではないことをLP・契約書に明記する。

## 4. 導入手順（全プラン共通の標準プロセス）
1. **診断**：`~/.claude/agents`・`.claude/agents`・`~/.claude/settings.json` を読み取り専用で確認
2. **棚卸し**：既存サブエージェントを explorer / worker / researcher に当てはめ、不足分だけ新規ドラフト。別モデル固定済みのものは変更せず一覧化
3. **阻害要因チェック**：`CLAUDE_CODE_DISABLE_ADVISOR_TOOL`・`DISABLE_TELEMETRY`・feature flag 取得停止・`CLAUDE_CODE_EFFORT_LEVEL` などを報告のみ
4. **diff提示**：全変更を diff で提出
5. **お客様の「go」で適用** → 動作確認 → 引き継ぎ資料

「勝手に書き換えない」こと自体を商品価値にする。
